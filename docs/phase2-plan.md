# 阶段二行动看板（StudySeatOps）

## 1. 阶段二验收目标
- 识别并定义全部用户故事
- 实现超过一半功能
- DevCloud 完成 DevOps 全流程（构建、测试、部署、流水线）
- 除自然语言交互外，核心基础功能优先完成

## 2. 里程碑与完成定义

### M1 需求与范围冻结
- 产出全量用户故事（含验收标准）
- 产出阶段二范围矩阵（Must/Should/Could/Won't）
- 完成定义：需求文档进入可评审状态

### M2 后端核心业务完成
- 身份认证、角色权限、自习室/座位/预约/签到/违约规则
- 核心接口可通过 Postman 或接口测试
- 完成定义：关键主流程可闭环

### M3 前端双端最小可用
- 学生端：登录、查询、预约、签到、历史
- 管理端：用户/教室/座位/预约/违约/系统参数/角色权限
- 完成定义：可完成端到端演示

### M4 自动化测试与质量门禁
- 单元测试覆盖核心规则
- 接口自动化测试覆盖主路径
- 覆盖率门禁 >= 70%
- 完成定义：CI 中测试稳定通过

### M5 DevOps 全流程
- Docker 化与 compose 一键启动
- DevCloud 构建任务、部署任务、流水线串联
- Test 自动部署，Prod 手动审批
- 完成定义：可演示一次提交触发全流程

## 3. 本周执行顺序
1. 初始化新工程骨架
2. 定义全量用户故事与验收标准
3. 后端模型与规则引擎先行
4. 前端最小闭环页面
5. 测试与流水线配置
6. Review 材料归档

## 4. 阶段二范围矩阵

### Must（阶段二必须完成）
- 账号登录注册
- 自习室与座位查询
- 整点预约（<=4小时，参数可配）
- 取消预约
- 签到码签到
- 预约提醒与超时违约处理
- 管理端 RBAC（角色、授权、权限菜单）
- 预约/违约记录查询
- CI/CD 流程可运行

### Should（有余力完成）
- 学生端历史预约一键复订
- 座位条件筛选（可充电/靠窗）
- 运营统计看板

### Could（可选）
- UI 自动化测试
- 智能推荐

### Won't（阶段二暂不做）
- 大模型自然语言助手深度接入
- 小程序端
